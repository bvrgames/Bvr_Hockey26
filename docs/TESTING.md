# Автотесты

Один раз: `npm install && npm run browsers` (Playwright + Chromium + WebKit, ~250 МБ в `~/Library/Caches/ms-playwright`).

| команда | что делает |
|---|---|
| `npm run check` | синтаксис: inline-скрипты `index.html` компилируются V8 (без запуска) + `node --check` для `tools/`, `server/` |
| `npm run smoke` | Chromium и WebKit headless: матч на автопилоте, 12 с в реальном времени + 10 с через freeze/step. Падает при любой ошибке консоли, исключении страницы, упавшем запросе, если матч не начался, часы/шайба стоят или ИИ не сделал ни паса, ни броска. Скриншоты: `shots/smoke-<браузер>.png` |
| `npm run smoke:chromium` / `smoke:webkit` | то же в одном браузере (без меню) |
| `npm run smoke:train` (входит в `npm run smoke`) | тренировка (docs/MENU_PLAN.md, раздел 5), Chromium и WebKit, на замороженном времени (`?frozen` + `__hk.step`): каждый из 10 уроков проходится до «выполнено» скриптом ввода урока (`__hk.trainBot(true)` — стик и кнопки, как у человека); уроки со случайностью в симуляции — до 3 попыток. Экран итога, «Следующий урок», медали сохраняются и видны в списке после перезагрузки (10 пройденных); свободная тренировка; Пауза → Главное меню → список уроков; урок клавиатурой из главного меню; кнопки тактики касанием; ни одного WebSocket и запроса за пределы машины; код уроков — отдельный файл (`assets/dist/train.<хеш>.js`): со страницей не грузится, грузится по запросу и при входе в «Тренировку» из меню. `__hk.train(i)`, `__hk.trainState()`, `__hk.trainLoad()` (обещание загрузки кода уроков), `__hk.trainJs()` |
| `npm run smoke:menu` (входит в `npm run smoke`) | меню (docs/MENU_PLAN.md) в фейковом полноэкранном Telegram, Chromium и WebKit: **первый запуск** — «Пройди тренировку» поверх главного, «Позже» → меню, после перезагрузки не появляется, «Начать» открывает урок 1; 3D-фон меню на «высоком» включается и гаснет со стартом матча (камера возвращается); **только клавиатурой** — главное → Режим игры → Против компьютера → подготовка (команда, 5 мин, тактика) → «Начать матч», матч идёт с этими настройками; Esc → пауза → Управление → назад → Настройки → назад → Главное меню; Быстрый матч повторяет сохранённый выбор, доигранный до конца матч — итог клавиатурой, в Профиле 1 матч (и после перезагрузки), Магазин открывается; язык и громкость музыки меняются и переживают перезагрузку; язык с главного. **Только геймпадом** (подменённый `navigator.getGamepads`): крестовина + A до матча, Start — пауза, B — продолжить. **Только касанием**: режим → против компьютера → длина → старт, кнопка паузы → Продолжить. BackButton Telegram: видна на подэкранах, скрыта на главном, её нажатие — назад, в матче — пауза. С другом (relay-mock): хост попадает на подготовку, когда друг вошёл, гость видит выбор хоста, «Начать» у гостя неактивна, матч у обоих с выбранными командой и длиной. Вертикаль: экран поворота со строкой трека; автозапуск звука запрещён — «коснись для звука», первое касание включает музыку; в матче музыка затихает |
| `npm run smoke:online [-- --browser webkit]` | хост-схема (`&net=host`): хост и гость в двух браузерах через `tools/relay-mock.mjs` (тот же протокол, что `server/worker.js`), оба «играют» случайным вводом 15 с. Падает, если события не дошли до гостя, статистика гостя ≠ хоста, нет `match:summary` у обоих или есть ошибки. Затем два запасных выхода по обычной ссылке: старый Worker без серверного режима (`startRelay(port,{noSrv:true})`) и сервер, который матч не начинает (`{deadSrv:true}`) — в обоих случаях матч должен сам пойти в хост-схеме у обоих |
| `npm run smoke:tg` | раскладка в полноэкранном Telegram: фейковый `Telegram.WebApp` (Bot API 8.0, `isFullscreen`, `safeAreaInset`, `contentSafeAreaInset`) в мобильном окне, горизонталь и вертикаль, RU/EN/ID, FPS вкл/выкл. Меню: все экраны (главное, режим, подготовка, комната, настройки, профиль, магазин, тренировка, обе вкладки правил, пауза, экран урока — в том числе кнопки тактики) в горизонтальных раскладках на RU/EN/ID — ничего под кнопками Telegram и вне безопасной зоны, тексты не обрезаны, пункты в своей колонке, ничего не наезжает на подвал (скриншоты `shots/ui/tg-menu-*.png`). Табло, пауза, FPS не заходят под кнопки Telegram (рисуются красным на `shots/ui/tg-*.png`) и в зону выреза, не перекрывают друг друга и экранные кнопки; подписи экранных кнопок помещаются. WebKit в Playwright не умеет вертикальную ориентацию — там «вертикаль» проверяется как узкая горизонталь |
| `node tools/pose-shots.mjs shots/springs --prefix after` | детерминированные скриншоты поз (живой игрок по скрипту, покадрово, камера сбоку): разгон, торможение, поворот, после броска. `__hk.benchSprings(lv, n)` — средняя цена кадра отрисовки с уровнем пружин `lv` |
| `npm run smoke:quality` | качество графики: автовыбор по устройству, динамическое разрешение раньше смены пресета (на смоделированном fps, холст реально уменьшается), цель 60 fps: пресет вниз после 3 с ниже 55 fps на минимальном разрешении, провалившийся уровень не возвращается до конца сессии (с первого провала), полоса 55–58 ничего не меняет, ручной выбор переживает перезагрузку и не перебивается, `#q` не сохраняется; печатает решения автовыбора на типичных устройствах. Последний шаг — в реальном времени: матч на «высоком» с «Авто», где «высокое» стоит +20 мс на кадр при любом разрешении (слабый GPU телефона, ~45 fps) — по настоящим часам кадра игра должна уйти на «среднее» за 5–13 с (обычно ~9) и вернуть 60 fps. `__hk.qInfo()`, `__hk.qGuessFor(info)`, `__hk.qTickSim(fps, n)` |
| `npm run smoke:lag [-- --scen A,B] [--trials 5] [--json out.json]` | задержки сетевого матча, сравнение хост-схемы и серверной (фаза 3.4) в мобильных условиях: у каждого игрока свой канал до сервера (RTT и джиттер как «jit» в панели ?debug, 1 % потерь = пачки после переотправки TCP). A: хост 140 мс / jit 55, гость 80 / jit 80 (тест RZYT); B: оба 140 / jit 80. В хост-схеме relay получает сумму обоих каналов, хост играет без задержки; в серверной матч считает `MatchRoom` в relay-mock, «(host)» — тоже сетевые цифры. Подготовка испытаний (дать шайбу, ничья шайба) — в той симуляции, что считает матч. Меряет на том, что нарисовано (rAF): отклик движения, пас/бросок (на экране и подтверждение), бросок по воротам (насколько нарисованная шайба уходит за линию ворот и сколько кадров прыгает назад), подбор, опережение своего игрока, рывки, поток снимков. `--rtt 0,80,150,250` — старый прогон хост-схемы по RTT. Падает только при ошибках страниц |
| `npm run smoke:server` | серверный режим в браузерах: хост по обычной ссылке (серверный режим — по умолчанию), гость с `&net=host` (режим всё равно задаёт комната). Сначала против `wrangler dev` (настоящий Worker + DO), затем против relay-mock в WebKit. Режим у обоих серверный, хост не считает матч сам (снимки в буфере), события и статистика у обоих одинаковые, 15-секундный матч заканчивается у обоих с одним счётом, реванш хоста перезапускает матч у обоих, без ошибок страниц. Обрывы связи: сокет гостя обрывается на 5 с (`__hk.netDrop(5)`) — у хоста «соперник переподключается…», сервер отдаёт команду гостя ИИ, чужой клиент с тем же кодом комнаты получает «комната занята», гость сам возвращается в тот же матч, его ввод снова доходит; перезагрузка страницы гостя возвращает его в матч по ключу из sessionStorage; затем на 40 с — гость через ~30 с сдаётся (меню, итог `result:'left'`), хост доигрывает против ИИ, в его итоге `disconnect.oppLeft` |
| `node tools/perf.mjs [--net solo\|guest] [--rates 1,4,6] [--q 0]` | разбивка времени кадра в мобильном окне (800×360 @2.625) при замедлении CPU ×N (CDP, только Chromium): sim, net, pose (скиннинг и пружины), draw (вызовы WebGL), marks, ovl (2D-накладка), hud (ввод и DOM), wait (остаток интервала — GPU/vsync), gpu (readPixels-проба). GPU остаётся маковским — инструмент ищет цену на CPU; цену на GPU смотри через `BVR_GL=swiftshader` (программный GPU как модель слабого телефона) и `__hk.benchGpu(n)` / `__hk.rskip({players,arena,ice,marks,ovl})` |
| `node tools/bake-lod.mjs [--ratio 0.22]` | запечь упрощённые модели игроков (LOD, meshoptimizer) в `HD_LOD` в index.html — те же вершины, меньше треугольников; рисуются на низком качестве. Перезапускать после замены моделей в `HD_DATA` |
| `node tools/relay-mock.mjs 8787 --lag 40 --jitter 15 --loss 1` | локальный релей с имитацией сети для ручной игры вдвоём |
| `?mode=srv` у первого вошедшего (игра просит сама) | relay-mock и Worker считают матч сами (`server/room-sim.js` на `shared/sim.js`); имитация сети в серверном режиме — на канале каждого игрока в обе стороны |
| `npm run relay` | локальный релей на :8787 — открыть два окна `?room=TEST&srv=http://127.0.0.1:8787` |
| `npm run sim:node [-- --seeds 3 --len 180]` | общая симуляция `shared/sim.js` в Node.js без браузера: полные матчи ИИ против ИИ с seed, проверка детерминизма (один seed — один матч). Короткий прогон входит в `npm run check`, как и проверка, что `<script src="shared/sim.js?v=…">` несёт хеш файла (`node tools/check.mjs --fix-version`) |
| `npm run room:proto` | серверный режим без браузеров (фаза 3.2): два WebSocket-игрока в комнате `?mode=srv` — сначала против `relay-mock`, затем против настоящего Worker'а в `wrangler dev` (workerd + Durable Object). hello с `srv:1` у обоих, cfg от хоста запускает матч на сервере, снимки ~30/с обоим с подтверждением ввода `a`, игрок едет по вводу, события с растущим `seq`, 15-секундный матч заканчивается `match:end`. Пропавшие игроки: чужой ключ в полной комнате и чужой без ключа на слот отключившегося (в том числе в пустой комнате с идущим матчем) получают `full`, молчащий 2 с игрок помечается в снимке (`w`), закрытый сокет — сразу, возврат с `?re=<роль>&tok=<ключ из hello>` даёт тот же слот и cfg идущего матча, матч живёт в пустой комнате и принимает вернувшегося хоста |
| `npm run smoke:api` | сначала правила монет (`server/coins.js`) в чистом Node.js с хранилищем в памяти — без Cloudflare; потом API монет и статистики (`server/api.js`) в `wrangler dev` с временной локальной D1 и тестовым токеном бота: подпись initData (нет, чужой токен, старше суток, подменённый user → 401), CORS, пустой профиль, победа с ИИ → 15 монет и профиль, тот же матч → 409, следующий сразу → 429, неправдоподобные итоги → 422, `left` → 0 монет, дневной лимит 100 → `capped`. Серверный матч в настоящей комнате (2 WebSocket-игрока, 15 с): отчёты со счётом комнаты → `match_duo`, другой счёт → 422 `mismatch`, неизвестный комнате матч → как с ИИ (`unverified`), хост с `team: 1` → 422; `X-Internal` снаружи до результатов комнаты не доходит. Игра в Chromium (`?api=`): итог из очереди уходит при запуске, профиль приносит монеты и статистику, итог матча — «+15 … · всего 30» на экране итога |
| `node tools/load.mjs [--net 4g,3g] [--cpu 4] [--runs 2] [--root dir]` | время загрузки как на телефоне: Chromium с эмуляцией сети (4G ~10 Мбит/с, RTT 100 мс; «медленный 3G» 400 кбит/с, 400 мс) и замедлением CPU, сервер как Vercel (`serve.mjs` `{vercel:true}`: brotli, ETag/304, Cache-Control из vercel.json). До меню и от «Старт» до матча с моделями, число запросов и байты — первый визит и повторный (кеш). `--root` — другая копия сайта (сравнение версий) |
| `node tools/pack-assets.mjs` | модели и текстуры: исходники в `assets/src/` (hd_data.json, hd_lod.json, PNG) → файлы с хешем в имени в `assets/dist/` (кешируются навсегда) + манифест `var ASSETS=` и `<link rel=preload>` в index.html. Запускать после любой правки в `assets/src/` (insert_clip.py, replace_clip.py, bake-lod.mjs пишут туда); `npm run check` падает, если забыли |
| `npm run balance [-- --seeds 20 --ai hard]` | баланс ИИ: N полных матчей на автопилоте с разными seed, полностью воспроизводимо (`?frozen` + `step`, без отрисовки). Средняя статистика по командам и откуда были броски (слот, после паса в разрез, добивание, издалека), время в зоне атаки на бросок. Команда 0 — автопилот на `normal`, команда 1 — соперник на `--ai`. `--json out.json` — все матчи с разбором |
| `npm run offball [-- --seeds 30 --mode entry\|zone --json out.json]` | игра без шайбы и пас в разрез (`tools/offball.mjs`, Node, `shared/sim.js` без браузера): мой центр по скрипту заводит шайбу в зону (`entry`) или держит её в зоне 1–2 с (`zone`) и даёт пас по Y; после приёма бросает, когда момент хороший. Считает открытых партнёров в момент паса (нет соперника ближе 2.5 м и линия свободна; из них — впереди шайбы; в позиции для броска), сколько пасов дошло, перехваты, броски / в створ / голы после паса, офсайды. Тот же seed — тот же эпизод |
| `node tools/offball-shots.mjs [shots/offball] [--prefix after]` | скриншоты того же (сценарий `zone`) в игре: ведение с подсказками над адресатами Y и A, рывок через 0.35 с после паса, 0.8 с после |

| `node tools/menu-shots.mjs before\|mock\|after [--lang en\|id] [--only main,prep] [--zones]` | скриншоты меню для переделки (docs/MENU_PLAN.md) в фейковом Telegram, горизонталь 844×390 и вертикаль 390×844: `before` — меню и пауза до переделки (запускать на старой версии), `mock` — макеты этапа 1 (`tools/menu-mock/index.html?s=экран`), `after` — новое меню игры: все экраны, пауза с подэкранами, итог, экран поворота; `--zones` рисует зоны кнопок Telegram и безопасную зону. Всё в `shots/menu/`, одной страницей — `shots/menu/index.html` |

Опции smoke: `--real N`, `--step N` (секунды), `--query "#q0"` (добавить к ссылке), `--inject "js"` (выполнить на странице после загрузки — например, чтобы убедиться, что тест падает на `console.error`), `--headed`.

WebKit — ближайшая локальная замена iPhone/Telegram, но не iPhone: производительность проверяй на устройстве.
На macOS Chromium рисует через ANGLE/Metal (реальный GPU). Без него (SwiftShader, `BVR_GL=swiftshader`) игра идёт ~3 fps.

## Параметры ссылки

| параметр | |
|---|---|
| `?autostart[=сек]` | сразу начать матч без меню (только одиночная игра); число — длина матча в секундах |
| `?autopilot` | команду игрока ведёт ИИ (в сетевом матче игнорируется) |
| `?seed=N` | предсказуемый `Math.random` — одинаковые решения ИИ |
| `?frozen` | старт в заморозке: игра идёт только через `__hk.step` — с `?seed` матч воспроизводится один в один |
| `?nomusic` | без музыки меню (тесты раскладки; с `?autostart` и `?frozen` музыки нет и так) |
| `?ai=easy\|normal\|hard` | уровень ИИ соперника поверх выбора в меню (не сохраняется; партнёры живого игрока всегда `normal`) |
| `?debug` | показать отладочные индикаторы (класс `.dbg`): скорость игрока, FPS внизу слева и на паузе, сетевые счётчики и разбивку времени кадра (панель слева сверху, раз в секунду: FRAME/cpu/wait/gpu, sim/net/pose/draw/marks/ovl/hud в мс, треугольники и вызовы отрисовки). Без флага они скрыты. В Telegram — `startapp=dbg` |
| `?net=host` | сетевой матч считает телефон хоста (запасная схема). Без флага матч считает сервер (фаза 3.5): оба игрока — как гость (снимки, предсказание движения, паса, броска, подбора). Решает тот, кто создаёт комнату; второй узнаёт режим от сервера. В Telegram — `startapp=host` / `host_КОД` / `host_dbg_КОД` (префиксы `host_` и `dbg_` в любом порядке; старый `srv_` принимается и ничего не меняет). Если Worker серверного режима не знает или матч не начал — хост-схема включается сама |
| `?side=1` | одиночная игра за команду 1 (проверка симметрии: `npm run balance -- --side 1`) |
| `#q0` / `#q1` / `#q2` | принудительное качество, автоподстройка и динамическое разрешение выключены, выбор игрока не перезаписывается |

## Отладка из консоли (`window.__hk`)

- `__hk.snap()` — сводка: состояние, часы, счёт, качество, fps, шайба, число бросков/пасов, ошибки
- `__hk.freeze()` / `__hk.unfreeze()` — остановить/продолжить игровой цикл
- `__hk.menu('prep'[, вкладка правил])` — открыть экран меню (`'main'` — сбросить стек); `__hk.menuState()` — слой (`menu`/`pause`/`result`/`null` при экране поворота), стек, пункт в фокусе, выбор подготовки, способ ввода, BackButton, длина матча; `__hk.music()` — трек, играет ли, заблокирован ли автозапуск, громкость; `__hk.start()` — «Начать матч» с текущей подготовкой
- `__hk.step(ms)` — синхронно прогнать `round(ms/16.7)` кадров по 1/60 с (работает и в заморозке)
- `__hk.errors()` — ошибки, пойманные `window.onerror` / `unhandledrejection`
- `__hk.stats()` / `__hk.match()` — статистика матча и мета + `summary` (docs/EVENTS.md); `__hk.ev` — шина событий
