# BVR Hockey 26 — заметки для Claude

Аркадный хоккей 5×5 для Telegram Mini Apps (бот @bvr_games_bot, приложение `hockeytg`). Один `index.html`
(WebGL2, без сборщика), общая симуляция `shared/sim.js`, сервер — Cloudflare Worker + Durable Object
(`server/`), фронт на Vercel (проект bvr-hockey26, команда bv-r, прод собирается из push в `main`).

## Правила работы

- Отвечать по-русски. Работа — фазами и короткими задачами; **каждая задача — отдельный коммит**.
- После каждой задачи push в `main` делаю сам, но только если прошли `npm run check`, `npm run smoke`,
  `npm run smoke:online`, `npm run smoke:tg`, `npm run smoke:lag` — **по кодам возврата**, каждый тест
  отдельно (`npm run -s X > log; echo $?`). Не судить по выводу через `tail`/`grep` — так однажды прошёл
  коммит с упавшим тестом. Если что-то упало — не пушить, чинить или сообщить.
  Для графики дополнительно `smoke:quality`, для эффектов матча — `smoke:feel`, для сети — `smoke:server`, `room:proto`, для API монет — `smoke:api`.
- Если задача говорит «сначала анализ и план» — остановиться после плана и ждать подтверждения.
- Worker деплою сам, без запроса: после правок в `server/` и прошедших тестов —
  `cd server && ../node_modules/.bin/wrangler deploy`; затем проверить, что деплой без ошибок и правка работает на проде
  (тестовое подключение к комнате или `wrangler tail`). Если wrangler просит логин/токен — сказать пользователю, что нужно.
  Никогда не деплоить прод Vercel через CLI (`--prod`) — прод строится из push.
- Supabase не используем вообще. Монеты/статистика — Worker + D1 с проверкой Telegram initData (HMAC),
  клиент монеты не начисляет (docs/EVENTS.md). CloudStorage Telegram — только настройки.
- Поведение симуляции не менять незаметно: после правок в `shared/sim.js` сверить `npm run balance --
  --json out.json` с прошлым прогоном (цифры матча должны совпасть, если правка не про ИИ/физику).
  Порядок вызовов `Math.random` — часть поведения.
- **Тестовый бот @Bvrtestbot — всё отладочное включено по умолчанию.** Проверка — просто открыть бота (и приглашение
  «С другом» из него), без ссылок, параметров и кодов. Признак в коде — `TEST.preview` (превью ветки: любой
  `*.vercel.app`, кроме прода `bvr-hockey26.vercel.app`); сейчас он включает `TEST.debug` (панель отладки). Новые тестовые
  функции сразу включать так же, по `TEST.preview`. В основном боте (прод) отладка выключена, как раньше (`?debug` /
  `startapp=dbg`).
- npm-кеш пользователя содержит root-файлы: при установке пакетов — `--cache <scratchpad>/npmcache`.

## Статус (04.10.2026)

Сделано: фазы A–E (автотесты, события, ИИ, следы на льду, пружины, качество графики), 3.0 (сетевая

- **Сеть.** По умолчанию — серверная схема (матч считает Durable Object, `server/room-sim.js` на
  `shared/sim.js`); решено после теста на двух телефонах по мобильному интернету (3.5). Хост-схема
  (матч считает телефон хоста) — запасная: сама, если Worker серверного режима не знает или матч не
  начал; вручную — `?net=host`, Telegram `startapp=host_КОД` / `host_dbg_КОД`. Режим комнаты задаёт
  тот, кто её открыл; второй узнаёт из hello. Замеры и тест на телефонах — в
  PHASE3_MULTIPLAYER_ARCHITECTURE.md.
  Обрыв связи в серверном режиме: за пропавшего (сокет закрыт / 2 с без ввода) играет ИИ, клиент сам
  возвращается в тот же слот (~30 с попыток), не вернулся — матч доигрывается против ИИ, в
  `match:summary` поле `disconnect`. Тест обрыва: `__hk.netDrop(сек)`. Слот отключившегося в идущем
  матче закреплён за ним: вернуться можно только с секретным ключом из hello (память + sessionStorage),
  остальным — «комната занята». Вход по Telegram user id (когда ключа нет) — не сделан, план в PHASE3.
- **Графика.** «Низкое»: LOD-модели, облегчённый шейдер (`#define LITE`), без MSAA, если игра стартовала
  на низком. «Среднее»: LOD-модели. «Высокое»: полные модели (качаются отдельно). Старт на Android: класс устройства из user agent Telegram (`Telegram-Android/… (модель; Android N; SDK N; LOW|AVERAGE|HIGH)`,
  04.10): LOW — «низкое», HIGH — «среднее» (если GPU не из слабых), AVERAGE — прежние признаки; iPhone — по экрану. Автоподстройка целится
  в 60 fps: разрешение вниз при <55 — только пока каждый шаг даёт ≥3 fps (нет прироста — шаг назад, ниже не идём,
  04.10), пресет вниз после 3 с <55 на этом «полу», провалившийся
  уровень не возвращается до конца сессии (сразу после первого провала, без повторной пробы).
  Замер (тормозит не заливка, ~47 fps на «высоком»): до «среднего» ~9 с (прогрев 2–3 с, один шаг разрешения, проба 2 с и
  обратно, 3 с ниже 55).

   выбирает её, ▲▼ работают; геймпад — стик вверх-вниз команда, влево-вправо карточка, LB/RB сторона, A — «Далее»;
   на втором экране длина/сложность/тактика и «Начать матч». С другом: гость листает свою карточку «Гости», хост видит
   его команду сразу, в матче у обоих те же команды.

## Бэклог

- **iPhone: рамка вокруг игры (06.10, отложено — делать через тестовый бот).** В Telegram на iPhone в полноэкранном режиме
  игра видна в окне с рамкой ~10 px со всех сторон и скруглёнными нижними углами, за рамкой — размытый фон; на Android —
  во весь экран. Игра рисует до краёв своего окна (`#stage` inset 0, холст 100 %, `viewport-fit=cover`) — сужено окно,
  которое даёт Telegram. Открытие напрямую (`/start` → «Хоккей»), не из хаба, — то же самое. Следующий шаг: в тестовом
  боте с панелью отладки вывести `innerWidth/innerHeight`, `screen`, `visualViewport`, `TG.isFullscreen`,
  `safeAreaInset`/`contentSafeAreaInset`, `TG.version` и сравнить с размером экрана.
- **Случайные числа матча зависят от FPS (найдено 02.10, фаза F).** В одиночной игре симуляция берёт глобальный
  `Math.random`, и клиент тоже: брызги льда (`addSpray`, решение «брызнуть» каждый кадр), `FX.old` (бывшая тряска),
  выбор анимации (`_useSlide`, начальная фаза клипа). Сколько этих вызовов — зависит от частоты кадров, поэтому один
  `?seed` в браузере даёт разные матчи на разных телефонах. Починка: всё визуальное — на `fxRand`, у симуляции свой
  генератор; цифры `npm run balance` сменятся — взять новую базу отдельным коммитом. Пока не трогаем.
