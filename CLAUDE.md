# BVR Hockey 26 — заметки для Claude

Аркадный хоккей 5×5 для Telegram Mini Apps (бот @bvr_games_bot, приложение `hockeytg`). Один `index.html`
(WebGL2, без сборщика), общая симуляция `shared/sim.js`, сервер — Cloudflare Worker + Durable Object
(`server/`), фронт на Vercel (проект bvr-hockey26, команда bv-r, прод собирается из push в `main`).

## Правила работы

- Отвечать по-русски. Работа — фазами и короткими задачами; **каждая задача — отдельный коммит**.
- После каждой задачи push в `main` делаю сам, но только если прошли `npm run check`, `npm run smoke`,
  `npm run smoke:online`, `npm run smoke:tg`, `npm run smoke:lag` — **по кодам возврата**, каждый тест
  отдельно (`npm run -s X > log; echo $?`). Не судить по выводу через `tail`/`grep` — так однажды прошёл
  коммит с упавшим тестом. Если что-то упало — не пушить, чинить или сообщить.
  Для графики дополнительно `smoke:quality`, для сети — `smoke:server`, `room:proto`.
- Если задача говорит «сначала анализ и план» — остановиться после плана и ждать подтверждения.
- Worker деплою сам, без запроса: после правок в `server/` и прошедших тестов —
  `cd server && ../node_modules/.bin/wrangler deploy`; затем проверить, что деплой без ошибок и правка работает на проде
  (тестовое подключение к комнате или `wrangler tail`). Если wrangler просит логин/токен — сказать пользователю, что нужно.
  Никогда не деплоить прод Vercel через CLI (`--prod`) — прод строится из push.
- Supabase не используем вообще. Монеты/статистика — Worker + D1 с проверкой Telegram initData (HMAC),
  клиент монеты не начисляет (docs/EVENTS.md). CloudStorage Telegram — только настройки.
- Поведение симуляции не менять незаметно: после правок в `shared/sim.js` сверить `npm run balance --
  --json out.json` с прошлым прогоном (цифры матча должны совпасть, если правка не про ИИ/физику).
  Порядок вызовов `Math.random` — часть поведения.
- npm-кеш пользователя содержит root-файлы: при установке пакетов — `--cache <scratchpad>/npmcache`.

## Статус (30.09.2026)

Сделано: фазы A–E (автотесты, события, ИИ, следы на льду, пружины, качество графики), 3.0 (сетевая
диагностика), 3.1–3.5 (серверный режим, теперь основной), производительность Android, автоподстройка, загрузка.

- **Сеть.** По умолчанию — серверная схема (матч считает Durable Object, `server/room-sim.js` на
  `shared/sim.js`); решено после теста на двух телефонах по мобильному интернету (3.5). Хост-схема
  (матч считает телефон хоста) — запасная: сама, если Worker серверного режима не знает или матч не
  начал; вручную — `?net=host`, Telegram `startapp=host_КОД` / `host_dbg_КОД`. Режим комнаты задаёт
  тот, кто её открыл; второй узнаёт из hello. Замеры и тест на телефонах — в
  PHASE3_MULTIPLAYER_ARCHITECTURE.md.
  Обрыв связи в серверном режиме: за пропавшего (сокет закрыт / 2 с без ввода) играет ИИ, клиент сам
  возвращается в тот же слот (~30 с попыток), не вернулся — матч доигрывается против ИИ, в
  `match:summary` поле `disconnect`. Тест обрыва: `__hk.netDrop(сек)`. Слот отключившегося в идущем
  матче закреплён за ним: вернуться можно только с секретным ключом из hello (память + sessionStorage),
  остальным — «комната занята». Вход по Telegram user id (когда ключа нет) — не сделан, план в PHASE3.
- **Графика.** «Низкое»: LOD-модели, облегчённый шейдер (`#define LITE`), без MSAA, если игра стартовала
  на низком. «Среднее»: LOD-модели. «Высокое»: полные модели (качаются отдельно). Автоподстройка целится
  в 60 fps: разрешение вниз при <55, пресет вниз после 3 с <55 на минимальном разрешении, провалившийся
  уровень не возвращается до конца сессии (сразу после первого провала, без повторной пробы).
  Замер (слабый GPU, ~45 fps на «высоком»): до «среднего» ~9–10 с (прогрев 2–3 с, 4 шага разрешения,
  3 с ниже 55).
- **Загрузка.** Модели и текстуры — `assets/dist/*.<хеш>` (кеш навсегда, vercel.json), исходники —
  `assets/src/`, сборка `npm run assets` (check падает, если забыли). `players-lo` (194 КБ) нужен всем,
  `players-hi` — только «высокому». Меню не ждёт моделей; «Старт» раньше — экран загрузки с процентами.

- **Меню (6 этапов, `docs/MENU_PLAN.md`).** Этап 1 утверждён с правками (раздел 0 плана). Этап 2 сделан, **ждёт
  проверки на телефоне**: новое меню в стиле спортивных игр только в горизонтали (в вертикали — «поверни телефон»
  с музыкой), главное меню с языком, Быстрый матч, Режим игры, подготовка матча (ИИ / с другом: гость видит выбор
  хоста), комната, Настройки, Правила (управление + правила хоккея), новая пауза и итог. Управление на всех экранах:
  касание, геймпад (крестовина, A/B, LB/RB, Start), клавиатура (стрелки, Enter/Esc, Q/E); «Назад» — BackButton
  Telegram. Музыка: 4 трека BvR (`assets/src/music/*.mp3` → AAC 96 кбит/с в `assets/dist`, `npm run assets`, нужен
  macOS `afconvert`), плашка «BvR — трек», на iPhone — с первого касания. Шрифт Fira Sans Extra Condensed
  (`assets/src/fonts`). На главном ещё Профиль (статистика матчей, локально + CloudStorage) и Магазин (витрина
  «скоро» — покупки ждут сервер монет Worker + D1). Этап 4 (Правила: схемы, устройство игрока) — готов.
  Дальше: 5 — тренировка (10 уроков), 6 — первый запуск и полировка.
  Ручное управление вратарём — отдельной задачей позже.

## Ждёт теста на телефонах

1. Серверная схема по умолчанию на двух телефонах: обычное приглашение из меню (без префиксов), в
   панели `startapp=dbg_<КОД>` первая строка должна быть `SERVER sim`. Запасная хост-схема —
   `startapp=host_dbg_<КОД>`. Обрывы: посреди матча выключить интернет на 5–10 с и включить (должно
   вернуть в матч само), и на минуту (у второго — «соперник не вернулся», матч доигрывается с ИИ).
   После Worker'а с временем шага в снимке (01.10) — нет ли телепортов у игрока с хорошей связью (был iPhone).
   Бросок по воротам (01.10): шайба не пролетает сквозь вратаря/ворота и не возвращается рывком.
0. **Новое меню (этап 2):** в вертикали — «поверни телефон» и играет трек (iPhone: «коснись для звука»), в
   горизонтали — меню; все экраны касанием, «Назад» Telegram; матч с другом по приглашению (гость видит выбор
   хоста); пауза → Управление / Настройки; музыка затихает в матче и возвращается в меню; язык сохраняется.
2. Android на «низком»: fps, строки `FRAME … gpu` и `q0 lite noAA …` (цель — стабильные 60).
3. iPhone на «высоком»: опускается ли на «среднее» при нагреве.
4. Время открытия в Telegram на мобильном интернете — первый раз и повторно.

## Где что лежит

- `PHASE3_MULTIPLAYER_ARCHITECTURE.md` — сетевая архитектура, статус 3.0–3.5, замер схем, обрывы связи.
- `docs/EVENTS.md` — шина событий, match:summary, экономика монет.
- `docs/TESTING.md` — все тесты и инструменты (`npm run …`), параметры ссылки, `window.__hk`.
- `docs/LOADING.md` — загрузка: таблица до/после, как устроены ресурсы.
- `docs/MENU_PLAN.md` — переделка меню: экраны и переходы, уроки тренировки, вес, этапы, вопросы.
- `index.html` — клиент; `shared/sim.js` — симуляция (браузер, Worker, Node; в `<script src>` с `?v=хеш`,
  `node tools/check.mjs --fix-version`); `server/worker.js` + `server/room-sim.js` — Worker и серверный матч;
  `tools/` — тесты и инструменты (relay-mock, perf, load, pack-assets, bake-lod, balance…).
- Отладка: `?debug` (в Telegram `startapp=dbg`) — панель сети и разбивка кадра; `__hk.perf()`,
  `__hk.benchGpu(n)`, `__hk.rskip({...})`, `__hk.boot()`, `__hk.qInfo()`.
